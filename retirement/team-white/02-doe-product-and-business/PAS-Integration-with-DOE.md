  1. [POST] /onboardings/{onboardingId}/commands/initializeplandocuments
  2. Response: 202 Accepted
2. A new endpoint will be created to "Get PAS Documents"
  1.
  2. DOE will use this endpoint to retrieve the unsigned documents that were generated by PAS so they can be presented to the user and sent through DocuSign as needed.
  3. This data will be retrieved directly from the new PAS Document table described above, including document content as base64.
  4. While plan documents are not ready, the DOE will poll this endpoint exponentially for a certain period of time awaiting their completion until it either completes successfully or faults

#### Workflow

1. DOE will call *"Initialize Plan Documents"*  endpoint in Onboarding.Api to initiate the process.
  1. This will happen after the final call to Save Data in Onboarding.Api has been made.
  2. This will kick off a new Plan Document Consumer described below
2. Plan Document Consumer
  1. Consumer will call "Initialize Plan Adoption Documents" in Plan Setup API.
    1. Plan Setup will provide the saved plan data to PAS
  2. Consumer will call "Generate PAS Documents" in Plan Setup API
    1. Plan Setup will make a request to PAS to generate the plan documents (via GenerateDocuments in PAS)
    2. A successful response will include a Request Id that can be used to track the progress of the request
  3. Consumer will call "Get PAS Documents Progress" in Plan Setup API to get the status of the generated documents from PAS (via GetProgress in PAS).
    1. Consumer will poll this endpoint exponentially until all documents have been generated or if a failure occurs
    2. If a failure occurs, the status will be saved into Msvc_Onboarding and the Plan Document Consumer will fault
  4. Consumer will call "Get PAS Documents Data" in Plan Setup API which will retrieve the package of generated documents
  5. Consumer will call "Get PAS Documents Details" in Plan Setup API which will return document metadata back from PAS (via GetDocuments in PAS)
    1. Plan document metadata will be preserved in the PAS Document table described above
    2. Rather than staging documents into a network location, they will be staged into our database with base64 content
    3. Plan Setup will map PAS documentum types to Cliff document types
      1. **TBD, will this be in Onboarding.Api?**
  6. Consumer will call "Update PAS Document Status" in Plan Setup API to update status of the PAS document package to "Signature Pending"
3. DOE will call "Get Plan Documents" from Onboarding.Api
  1. This endpoint will be polled exponentially for a certain period of time while documents are being prepared until either:
    1. Documents are fully staged and accessible via Onboarding.Api
    2. Document generation faulted in PAS and the process cannot be continued
  2. When documents are not ready, this endpoint will return a validation error message indicating that they are either in progress or faulted
  3. When documents are ready, this same endpoint will instead return the plan document metadata, including the base64 content for each document
4. User will view and sign documents from within DOE until all documents are complete with signatures as needed.
  1. DOE will know which documents require a signature based on the "Is Signature Required" flag in PAS Document table
5. DOE will make a request to send each signed document back to Onboarding.Api (calling the existing "PUT Document" endpoint, unchanged)
  1. DOE will know which documents to send back based on "Is Excluded from Cliff" flag in PasDocument table
6. DOE will call "Initialize Plan Establishment" in Onboarding.Api, which will begin the final stages of our Onboarding sags
  1. Onboarding.Api will import signed documents into Cliff, which will include anything present in the existing Document table of Msvc_Onboarding
  2. Onboarding.Api will make a request to Plan Setup to "*Update PAS Document Status* "
    1. PAS document package status will be updated to "Signature Complete"
