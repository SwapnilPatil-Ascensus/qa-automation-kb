##### Analysis of InitializePlanAdoptionDocuments  function in Onboarding.Setup.Plan API.

1. Input parameter Datapoints (#4) is a dictionary parameter which collects data from foundation which has been mentioned above, once this parameter pass to InitializePlanAdoptionDocuments API, it does following operation. Pls ref function GetPlanAdoptionDocumentParameters() for details.
  1. Get Default data from MSVC_Onboarding_Ark database (ref. function GetPlanAdoptionDocumentDefaultsData()) for input planId , offering and product.
  2. Add this data in local collection based on Offering and Product (Ref. GetPlanAdoptionDocumentParameters()) in PlanSetupEngine.cs
  3. Identify if product is P4O or P4M. (Ref function GetInstance()).
  4. Get data from various ARK tables and store it in collection. Ref. **BuildDataPointDictionary** () function **Plan4OnePlanAdoptionDocumentData** .cs class AND **BuildDataPointDictionary** () function **Plan4MostPlanAdoptionDocumentData** .cs class for details.
  5. Default data and ARK Table data will then add in same input #4 collection.
  6. Now #4 collection have data which has been setup in foundation + default data and ARK table data.
2. Input parameter ServiceAgreementDataPoints (#5) is a dictionary parameter collects data from foundation which has been mentioned above, once this parameter pass to InitializePlanAdoptionDocuments API, it does following operation. Pls ref function GetPlanAdoptionDocumentParametersServiceAgreements() for details.
  1. Get Default data from MSVC_Onboarding_Ark database (Ref. function GetPlanAdoptionDocumentDefaultsDataServiceAgreements()) for input planId , offering and product.
  2. Add this data in local collection based on Offering and Product (Ref. GetPlanAdoptionDocumentParametersServiceAgreements()) in PlanSetupEngine.cs
  3. Identify if product is P4O or P4M. (Ref function GetInstance()).
  4. Get data from various ARK tables and store it in collection. Ref. **BuildServiceAgreementDataDictionary** () function **Plan4OnePlanAdoptionDocumentData** .cs class AND **BuildServiceAgreementDataDictionary** () function **Plan4MostPlanAdoptionDocumentData** .cs class for details.
  5. Default data and ARK Table data will then add in same input #5 collection (i.e.ServiceAgreementDataPoints).
  6. Now #5 collection have data which has been setup in foundation + default data and ARK table data.
3. The data gather in #1 and #2 is now set to respective object of class PlanAdoptionDocumentData.
4. Some other properties like planId, PartnerId, DocumentSponsorId, dateConversionSubmitted etc. are assigned. There properties are defined in PlanAdoptionDocumentData class.
  1. Properties like DocumentSponsorId, PartnerId are coming from appsettings.json. Ref. **PlanAdoptionDocumentSettings** key in appsettings.json. Values for these properties are different for different environments and configured in Octopus variables as below.
    1. | **#** | **Properties** | **DEV** | **QA** | **PRO** | **Comments** | | --- | --- | --- | --- | --- | --- | | 1 | ProductId | 161 | 86 | 0 | <br> | | 2 | DocumentSponsorIdPlan4One | 9751 | 492 | 17 | DocumentSponsorId- 9751 is not working . | | 3 | DocumentSponsorIdPlan4Most | 2 | 500 | 3 | <br> | | 4 | PartnerIdPlan4One | 24128 | 143 | 55 | <br> | | 5 | PartnerIdPlan4Most | 24127 | 142 | 54 | <br> |
    2. All these properties are set in InitializePlanAdoptionDocuments() function, refer for details.

1. Now PlanAdoptionDocumentData , has two collections (i.e. #1 and #2) and properties which are mentioned above in #4.
2. This PlanAdoptionDocumentData object then pass to PAS API - [https://pasdev.ascensus.com/conversion/massimport/api/import/](https://pasdev.ascensus.com/conversion/massimport/api/import/) , which eventually insert data in PAS system.
